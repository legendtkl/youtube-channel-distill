# 蒸馏方法论 · 从转写稿到一个 skill

转写稿到手后，目标是把博主**反复使用的思维模型/指标/决策规则**固化成一个渐进式披露 skill。核心难点是**量大**——几十上百期、每期几千到几万字，单 context 读不完也读不好。解法 = **分批并行提炼 → 按类合并**。

---

## 第 1 步 · 定类别（5–8 个）

类别 = 输出 skill 的 `references/` 文件。**先扫一遍标题清单 + 抽读 3–5 篇转写稿**，看博主反复在讲什么，按他的实际主题划分，别硬套。

- **财经/投资博主默认起点**（对标 talkjun，按需增删）：
  1. `principles.md` —— 心法/哲学/行为金融/情绪纪律
  2. `workflow-and-indicators.md` —— 分析流程/指标/择时/盘面
  3. `valuation.md` —— 估值方法/案例
  4. `earnings.md` —— 财报解读/打分模板
  5. `macro.md` —— 宏观/政策/利率
  6. `portfolio-and-risk.md` —— 仓位/风控/组合
  7. `stock-and-sector-views.md` —— 强时效的个股/板块观点（单独隔离，标"仅参考"）
- **非财经博主**：把上面替换成该领域的反复主题（如科技测评 = 选购框架/参数解读/品类对比/避坑；健身 = 训练原则/动作库/饮食/恢复）。

> 老李玩钱这类频道（看标题：7 巨头点位、华尔街买卖股、ETF 定投、报税/税损收割、买入价位、特斯拉目标价、复盘）偏**实操/点位/操作建议**，类别可考虑：心法与仓位纪律 / 选股与买卖点位框架 / 板块与个股观点 / ETF 与定投 / 大盘与择时 / 税务与账户管理。**以实际转写为准**。

定完类别，写一句话**类别定义**（这条要点该归哪一类的判据），fan-out 和 merge 的 subagent 都靠它对齐。

---

## 第 2 步 · Fan-out 提炼（并行 subagent）

把转写稿分批（每批 ~8–12 篇，视长度），每批一个 subagent。可用 **Agent 工具**手动并行，或在用户明确要 workflow 时用 **Workflow** 工具 pipeline。

每个提炼 subagent 的提示词模板：

```
你在帮我蒸馏 YouTube 博主「<频道名>」的方法论。下面是他若干期视频的 ASR 转写稿
（每篇开头有 # 标题 | 日期 | vid 头）。

任务：把这些稿子里**反复出现的、可复用的**思维模型、指标、估值/分析方法、决策规则、
口头禅式的原则提炼成结构化要点。忽略一次性的闲聊、广告口播、纯时效性新闻复述。

按这 N 个类别归类输出（每条要点注明来自哪一期/vid）：
1. <类别1>：<判据>
2. <类别2>：<判据>
...

每条要点写成：【类别】一句话观点 + 必要的展开/阈值/案例（出处 vid/日期）。
只输出要点，不要总结这批视频讲了啥。
```

让每个 subagent 把结果**落盘**到 `_findings/batch_NN.md`（或直接返回结构化文本由主 agent 汇总）。落盘更稳——量大时 subagent 返回值也会很长。

> 规模建议：50 期 → 5–6 个提炼 subagent；100 期 → 8–10 个。**坑：不要全盘 `grep -rl ... /`**，会触发 ugrep 扫满 CPU 数小时——所有检索限定到转写目录。

---

## 第 3 步 · 按类 merge（每类一个 subagent）

每个类别派一个 merge subagent，读**所有** `_findings/` 里属于该类的要点：

```
下面是从「<频道名>」多期视频里提炼的、归到【<类别>】的所有要点（可能重复、零散、
表述不一）。请合并成一篇结构化的 reference（中文，markdown）：

- 去重、合并同类项，用博主自己的语言和框架表述。
- 高频反复强调的 → 放前面、给足展开；只出现一两次的边角 → 精简或删。
- 有阈值/公式/案例的要点尽量保留具体数字和出处。
- 强时效的个股/板块判断要标注「仅参考，以当时为准」。
- 输出可直接作为 references/<类别>.md 的正文。
```

产出落到输出 skill 的 `references/<category>.md`。

---

## 第 4 步 · 提第一性原理 + 写 SKILL.md

通读各类 merge 结果（或让一个 subagent 专门做），提炼博主**最核心、最反复强调**的 5–10 条原则，作为 SKILL.md 常驻内容。SKILL.md 结构：

```markdown
---
name: <kebab-case，体现博主，如 laoli-stock-playbook>
description: >
  <一句话定位> ... Use this skill whenever the user wants <博主风格分析/...>。
  Triggers: "<塞满中英口语触发词、博主名、频道名、招牌术语>" ...
metadata:
  type: skill
---

# <频道名> · <一句话定位>

模仿 YouTube 频道「<名>」(@handle，主播<名>) 的<领域>方法。本 skill 把他在 ~N 期视频里
反复使用的思维模型、指标、决策规则固化下来。

> 数据/事实另取：方法论是骨架，具体数字让使用方用数据类 skill 现取，不在此写死会过期的数字。

## 渐进式披露 · 怎么用
| 用户想要 | 读这个 |
|---|---| ...（路由表）

## <N> 条第一性原理（内化这些）
1. ... （博主最核心的几条）

## 标准流程骨架
...

## 输出风格
...
```

`description` 是语义路由的命中关键——**把用户可能的所有说法塞进去**（中英、口语、术语、博主名、频道名、招牌句）。

---

## 第 5 步 · 写 sources.md + 保留语料

```markdown
# 框架溯源 · <频道名>
- 频道：<url>
- channelId：`UCxxxx`；uploads 列表：`UUxxxx`（UC→UU）
- 主播 / 定位 / 订阅数 / 更新节奏
- 提炼样本：最近 N 期，期号/时间区间 <...>，全部 ASR 转写
- 原始转写稿留存在 `<path>/<channel>_transcripts/`

## 如何更新本框架
1. 列清单：scripts/list_videos.sh "<url>" <N>
2. 转写：uv run scripts/transcribe.py --channel "<url>" --limit <N> --out <dir>（断点续跑）
3. fan-out 提炼 + 按类 merge（见 distillation-method.md）
```

原始转写稿务必保留——下次增量更新（补更老/更新的期）直接续跑，已转写的会跳过。

---

## 质量准则

- **忠于博主**：用他的语言、他的框架，不要塞入你自己的投资观点或别的博主的方法。
- **方法 > 结论**：固化"怎么分析"，而非"他看涨某股"这种会过期的结论；强时效结论隔离并标注。
- **渐进式披露**：SKILL.md 精简、常驻；细节进 references，用到才读。
- **可重跑**：任何人照 sources.md 能把整条流水线再跑一遍、增量更新。
- **诚实标注样本边界**：写清覆盖了哪些期、时间跨度，没覆盖的别假装覆盖。
